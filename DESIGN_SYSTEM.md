# PitchKit Design System

A reference for the visual language used across PitchKit's marketing site, app UI, and internal tools. This describes what's actually in the codebase — not an aspirational redesign.

The design language is **dark, mono-accented, and a little luxe**: near-black surfaces, a single amber/gold accent, sparse use of color, generous whitespace, and subtle motion. It's meant to feel like a serious tool for people who care about how things look (the audience: freelance designers and agencies).

> **Scope:** This applies to the PitchKit *product* — landing page, dashboard, create flow, settings, blog. It does **not** apply to AI-generated client preview HTML at `/preview/[slug]` — those are bespoke designs generated by Claude per prospect, with their own design language each time.

---

## 1. Color

All colors live in `tailwind.config.ts` and `app/globals.css` (CSS variables). Reach for the named tokens; only drop to raw hex when prototyping.

### Surface

| Token | Hex | Tailwind | Use |
|---|---|---|---|
| Background | `#0a0a0a` | `bg-[#0a0a0a]` (body default) | Page background |
| Surface | `#111111` | `bg-surface` | Cards, panels, inputs |
| Surface light | `#191919` | `bg-surface-light` | Raised surfaces, hover states |
| Border | `#222222` | `border-[var(--border)]` | Default 1px borders |
| Border light | `#333333` | `border-[var(--border-light)]` | Hover/focus borders |

The body in `app/layout.tsx` is hard-coded to `bg-[#0a0a0a] text-neutral-200`. Don't override the page background — let surfaces float on top of it.

### Accent (amber/gold)

The single brand accent. **Use sparingly** — it should feel like a highlight, not a fill. Most pages have one or two accent elements per viewport.

| Token | Hex | Tailwind | Use |
|---|---|---|---|
| Accent | `#f59e0b` | `bg-accent`, `text-accent`, `border-accent` | Primary CTAs, key highlights |
| Accent light | `#fbbf24` | `bg-accent-light` | Hover state on primary CTAs |
| Accent dark | `#d97706` | `bg-accent-dark` | Pressed/active states |

Tinted accent (very common pattern for chips, soft backgrounds, glows):

- `bg-accent/5`, `bg-accent/10` — subtle wash, used on chip backgrounds and feature-card icon wells
- `border-accent/20` — soft accent border on chips and tinted cards
- `text-accent/60` — de-emphasized accent text (helper copy under accent UI)

### Text

Default body text is `text-neutral-200` (set on `<body>`). Use the scale below for hierarchy — don't introduce new neutrals.

| Token | Use |
|---|---|
| `text-white` | Headlines, key emphasis on dark surfaces |
| `text-neutral-200` | Body default |
| `text-neutral-300` | Secondary body |
| `text-neutral-400` | Tertiary, captions on cards |
| `text-neutral-500` | Muted helper text, labels (most common muted color) |
| `text-neutral-600` | Placeholders, decorative icons |
| `text-neutral-700` | Disabled, very faint |
| `text-black` | **Only** on accent backgrounds (the amber CTA) |

### Status

| Use | Tailwind | Notes |
|---|---|---|
| Error text | `text-red-400` | |
| Error surface | `bg-red-500/5 border border-red-500/20` | Tinted box pattern |
| Success text | `text-emerald-400` | |
| Warning text | `text-amber-400` | Distinct from accent — use for warnings only, not branding |

## 2. Typography

### Fonts

Both fonts are loaded as variable fonts via `next/font/local` in `app/layout.tsx`:

- **Geist Sans** (`font-sans`, default) — UI, headlines, body
- **Geist Mono** (`font-mono`) — URL inputs, slugs, code, anywhere a "technical" feel is wanted

### Scale

PitchKit uses a compact scale. Most UI lives in `text-xs` and `text-sm`. Reserve large sizes for marketing-page headlines.

| Tailwind | Common use |
|---|---|
| `text-xs` (12px) | Chips, captions, helper text, dense table cells |
| `text-sm` (14px) | **Default for buttons, form fields, most UI text** |
| `text-base` (16px) | Long-form body (rare in app UI) |
| `text-lg` (18px) | Subheads inside cards |
| `text-xl` / `text-2xl` | Section headings inside the app |
| `text-3xl` / `text-4xl` | Page titles, marketing subheads |
| `text-5xl` / `text-6xl` / `text-7xl` | Landing-page hero headlines only |

### Weight

- `font-medium` — buttons, labels, links
- `font-semibold` — primary CTAs, emphasized inline text, card titles
- `font-bold` — headlines, hero copy

### Decorative

- `.text-gradient` — white → accent → white linear gradient text-fill, used for hero headline accents. Don't apply to body copy (low contrast at small sizes).

## 3. Spacing & Layout

### Section rhythm

Marketing sections use **`py-16`** (smaller) or **`py-24`** (hero/major) vertical padding. Stick to those two values for top-level sections.

### Container

Pages use `max-w-xl` / `max-w-2xl` / `max-w-5xl` / `max-w-6xl` `mx-auto px-4 sm:px-6` depending on density. There is no shared `<Container>` component — that's intentional, layouts are case-by-case.

### Gaps

`gap-1`, `gap-1.5`, `gap-2`, `gap-3` dominate (tight UI). `gap-4`+ for marketing layouts and feature grids.

### Padding inside components

- **Inline chips:** `px-2 py-0.5` (very common for accent chips)
- **Buttons (default):** `px-5 py-2.5`
- **Buttons (compact):** `px-3 py-2` or `h-8 px-3`
- **Inputs:** `px-3 sm:px-4 py-4`
- **Cards:** `p-3` (compact) or `p-5` / `p-6` (marketing)
- **Toast/alert boxes:** `p-3`

---

## 4. Radius

PitchKit favors **soft rounded corners**, but matches radius to component scale.

| Tailwind | Use |
|---|---|
| `rounded-lg` (8px) | Default for buttons, small icon wells, compact cards |
| `rounded-xl` (12px) | Default for inputs, alert boxes, cards, larger CTAs |
| `rounded-2xl` (16px) | Hero panels, large feature-icon wells |
| `rounded-full` | Chips, pills, avatars, badge indicators |

Do not use `rounded`, `rounded-sm`, `rounded-md`, or `rounded-3xl` — they're not part of the system.

## 5. Components & Patterns

These are not React components (PitchKit deliberately does not use a component library) — they are *recipes* you should keep consistent.

### 5.1 Primary CTA (the amber button)

The single most important pattern in the app. Used for "Analyze," "Generate," "Buy credits," etc.

```tsx
<button className="inline-flex items-center gap-2 px-5 py-2.5 bg-accent hover:bg-accent-light text-black text-sm font-semibold rounded-xl transition-all duration-200 hover:shadow-lg hover:shadow-accent/20">
  Generate
</button>
```

**Variants in use:**
- Compact (inside an input): `m-1.5 px-3 sm:px-5 py-2.5 ... rounded-lg`
- Mini (table row actions): `px-3 py-2 ... text-xs ... rounded-lg`
- Fixed-height row: `h-8 px-3 ... rounded-lg`

**Always:** `text-black` on the amber, `font-semibold`, hover lifts the shadow with `hover:shadow-accent/20`.

### 5.2 Secondary button

Outlined, surface-tinted. Used for "Cancel," "Edit," "Sign in with Google" alongside a primary CTA.

```tsx
<button className="px-5 py-2.5 bg-surface hover:bg-surface-light border border-[var(--border)] hover:border-[var(--border-light)] text-neutral-200 text-sm font-medium rounded-xl transition-all duration-200">
  Cancel
</button>
```

### 5.3 Card

Default container for content blocks.

```tsx
<div className="bg-surface border border-[var(--border)] rounded-xl p-5">
  ...
</div>
```

For interactive cards, hover with `hover:border-[var(--border-light)]` and optionally a subtle accent tint.

### 5.4 Input

```tsx
<input
  className="w-full px-4 py-3 bg-surface border border-[var(--border)] rounded-xl text-white text-sm placeholder:text-neutral-600 focus:outline-none focus:border-accent/50 font-mono"
/>
```

URL/slug/email inputs use `font-mono`. Free-text inputs use the default sans.

### 5.5 Chip / Pill

Tiny tags. Always rounded-full, always small text.

```tsx
<span className="inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-[11px] font-medium bg-accent/10 text-accent border border-accent/20">
  New
</span>
```

Other tints follow the same shape: `bg-emerald-500/10 text-emerald-400 border-emerald-500/20`, etc.

### 5.6 Tinted alert box

Used for inline errors, notices, and toasts.

```tsx
<div className="p-3 bg-red-500/5 border border-red-500/20 rounded-xl text-red-400 text-xs">
  {error}
</div>
```

Swap the color family (`accent`, `emerald`, `red`, `amber`) without changing the structure.

### 5.7 Icon well

Square soft-tinted container behind an SVG. Used in feature lists and section headers.

```tsx
<div className="w-8 h-8 rounded-lg bg-accent/10 flex items-center justify-center text-accent">
  <Icon className="w-4 h-4" />
</div>
```

Larger marketing variant: `w-16 h-16 rounded-2xl`.

### 5.8 Icons

PitchKit uses **inline SVGs**, not an icon library. They are defined as small local components inside the file that uses them (see `components/url-input.tsx`).

- Default size: `w-4 h-4` or `w-5 h-5`
- `stroke="currentColor"`, `strokeWidth="2"`, `strokeLinecap="round"`, `strokeLinejoin="round"`
- Inherit color via `text-*` on the parent

Do not add an icon dependency — keep them inline.

## 6. Motion

All keyframes and animation utilities live in `app/globals.css`. Don't add new animations there casually — these were chosen to be subtle and consistent.

| Utility | What it does | When to use |
|---|---|---|
| `animate-fade-in-up` | 0.7s opacity + 24px Y rise | Section reveals on scroll/load |
| `animate-fade-in` | 0.6s opacity only | Modals, conditional content |
| `animate-float` | 6s gentle Y oscillation | Decorative hero elements only |
| `delay-100`…`delay-700` | Animation-delay helpers | Stagger children of a fade-in group |

Default transitions for hover states: `transition-all duration-200` (UI) or `duration-500` (decorative glows).

---

## 7. Decorative effects

Custom utilities defined in `app/globals.css`:

- **`.glow-amber`** — large soft amber drop-shadow. Use behind hero CTAs and feature highlights, **once per page max**.
- **`.text-gradient`** — animated white→accent→white text fill. Headline accents only.
- **`.shimmer-border`** — animated horizontal accent shimmer. Use as a 1px decorative top/bottom strip on key sections.
- **`.noise-bg`** — fractal noise overlay (3% opacity). Apply to hero / large surfaces to break up flat dark.

Use no more than **one** decorative effect per surface. They are accents, not fills.

### Scrollbar

Custom thin scrollbar (`6px`, `#333` thumb on `#0a0a0a` track) is set globally in `globals.css`. Don't override per component.

## 8. Conventions & rules of thumb

- **One accent per screen.** If a screen has more than two amber elements, demote one to neutral.
- **Use `bg-accent/10` more than `bg-accent`.** Soft tints feel more premium than solid fills.
- **Black text on amber, white on accent backgrounds — never inverted.** `text-black` paired with `bg-accent` is the only place black text appears.
- **Borders over shadows.** PitchKit relies on `border-[var(--border)]` for separation, not drop shadows. The only shadows in regular use are `shadow-accent/20` on the primary CTA hover.
- **No component library.** Don't introduce shadcn, Radix, MUI, etc. Match an existing recipe or write the markup inline.
- **No global state library.** React hooks only.
- **Geist mono for technical strings.** URLs, slugs, IDs, code — always `font-mono`.
- **Compact density.** Default to `text-sm` and `text-xs`; resist the urge to scale up to `text-base` for app UI.

---

## 9. What's *not* in the system

If you find yourself reaching for any of these, stop and either reuse an existing pattern or talk to Stevan:

- A second accent color (no blue, no green primary, no gradient palettes)
- Light mode (the app is dark-only — `<html className="dark">` is hard-coded)
- Drop shadows for elevation (use borders + surface-light)
- New radii outside `lg / xl / 2xl / full`
- New animations beyond what's in `globals.css`
- Component libraries
- Light surfaces (`bg-white`, `bg-neutral-100`, etc.)
